# Steps 9-10 — `fix/verify-build-sha`

## No new endpoint was needed

`/api/ping` already returns `process.env.VERCEL_GIT_COMMIT_SHA` (`src/app/api/ping/route.ts:19`), Bearer-gated by `CRON_SECRET`. I used that rather than adding `/api/build`, so no new publicly-readable surface exists just to make the battery work.

## What changed — 3 files

- **`scripts/verify/lib/build.mjs`** (new) — `servedCommit(base)`: GETs `/api/ping` with the Bearer secret, throws with the reason on a non-200 or a missing/`"unknown"` commit.
- **`scripts/verify/run.mjs`** — the gate, placed before `publishedStreetSlugs()`, so it runs before the first network read of any content.
- **`scripts/verify/README.md`** — documents the gate and the new exit code.

Expected SHA is `EXPECT_SHA` when set, otherwise `git rev-parse HEAD`. Running the battery from a branch is an implicit claim that the branch is what is deployed, so HEAD is the honest default rather than a silent skip. Exit codes are now `0` pass, `1` a content assertion failed, `2` the battery declined to run — reusing the existing "did not run" code rather than colliding with a real failure.

## Honest limit

This catches *the wrong deployment*. It does not catch *the right deployment serving a stale cached page* — which is what actually bit bronte-street today (`X-Vercel-Cache: HIT`, `Age: 1424`, same SHA). Closing that needs a freshness assertion on the page response, not a build assertion. Say the word and I will add it.
